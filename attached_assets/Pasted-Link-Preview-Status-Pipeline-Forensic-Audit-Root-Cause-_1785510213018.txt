Perform a complete forensic audit of the entire link preview, status, and rich-message pipeline built with @crysnovax/baileys.

The objective is not to make previews "look better." The objective is to restore the native WhatsApp/Baileys preview pipeline exactly as intended while preserving the existing "use-as-is" preview system.

Do not implement fake previews.

Current Situation

The existing "Use As Is" preview system works correctly.

If a message already contains a hydrated WhatsApp preview, the bot correctly preserves and forwards it.

Do not modify this behavior.

The problem exists only when the bot must generate a preview from a plain URL.

That pipeline has gradually degraded after multiple updates.

The latest code now produces poorer previews than older builds.

This indicates that the native preview generation flow has been partially broken.

Your job is to identify exactly where.
